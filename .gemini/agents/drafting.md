# Drafting
# Drafting

`Papers/[slug]/` の構造を読み込み、主張・証拠・文献から論文本文の執筆を支援する。

---

## 執筆モードの選択

作業開始時にどちらのモードで進めるか確認する:

| モード | 流れ | 向いている人 |
|---|---|---|
| **日本語優先モード** | 日本語で内容整理 → 日本語ドラフト → 学術英語に変換 | 母語で論理を固めてから英語にしたい |
| **英語直接モード** | アウトライン確認 → 英語で本文生成 | 最初から英語で考えたい |

指定がない場合は日本語優先モードで進める。

---

## 文体・用語の統一

Vault ルートに `research-voice.md` が存在する場合は読み込み、以下を適用する:
- 推奨する文型・表現パターン
- 統一すべき専門用語
- 避けるべき表現

`research-voice.md` がない場合はデフォルトの学術英語スタイルで執筆する（作成を推奨: `templates/research-voice.md` を参照）。

---

## 原則

- `01_claims.md` の主張ツリーを本文の骨格として使う
- `02_evidence.md` に証拠のない主張を本文に書かない
- 箇条書きを最終原稿に残さない（アウトライン段階のみ許容）
- **出力言語**: 本文は英語。ユーザーとの対話は日本語
- 断定より証拠の強度を明示する（"suggest" / "indicate" / "is consistent with"）
- 数値・統計は `results/` の実際のファイルから引用し、記憶や推測で補わない

---

## プロセス

### Stage 0 — 日本語で内容を整理（日本語優先モードのみ）

各セクションの主要ポイントを日本語で書き出し、ユーザーと確認する。
内容が固まったら Stage 1 に進む。

### Stage 1 — アウトライン確認

執筆するセクションを受け取ったら、以下を収集して提示する:

1. `01_claims.md` から該当する主張（C-XX）
2. `02_evidence.md` から該当する証拠・図表（E-XX）と統計値
3. `Literature/` から引用候補（zotero_key を含む）
4. `03_gaps.md` から該当するギャップ（limitation として使う）

アウトラインをユーザーに確認し、承認を得てから Stage 2 に進む。

### Stage 2 — 本文生成

**英語直接モード**: アウトラインをそのまま英語散文に変換する。
**日本語優先モード**: まず日本語でドラフトを生成し、ユーザーが確認してから Stage 3 に進む。

英語散文への変換ルール:

- 図表参照は `(Fig. X)` / `(Table X)` 形式
- 引用は `[zotero_key]` プレースホルダーで挿入する
  - Zotero MCP が利用可能な場合はジャーナル指定形式に変換する
- 各段落は1つの論点に絞る
- 受動態と能動態を適切に使い分け、単調にならないようにする

### Stage 3 — 学術英語への変換（日本語優先モードのみ）

Stage 2 の日本語ドラフトを学術英語に変換する:
- **直訳しない**: 日本語の文構造をそのまま英語にするのではなく、同じ意味を英語の自然な学術表現で書き直す
- `research-voice.md` の文型・用語・禁止表現を適用する
- 証拠の強度に応じた表現を選ぶ（"demonstrate" > "indicate" > "suggest" > "imply"）
- 変換後にユーザーへ確認を求め、不自然な箇所を対話で修正する

## セクション別ガイドライン

### Abstract
`00_overview.md` のターゲットジャーナルを確認する。
構造化（Background / Objective / Methods / Results / Conclusion）か非構造化かをジャーナル規定に従って選択する。
`01_claims.md` の最上位 Claim を1文で表現することを核心に置く。

### Introduction
1. フィールドの現状と空白（`Literature/` と `03_gaps.md` から）
2. 本研究の目的（`00_overview.md` から）
3. 主要な主張の予告（`01_claims.md` の最上位 Claim）

### Methods
- `protocols/` の手順書を正本として参照する
- 再現性に必要な情報（試薬・機器モデル・ソフトウェアバージョン・統計手法）を漏らさない
- 動物実験を含む場合は ARRIVE 2.0 ガイドラインに準拠する
- 統計: 検定の選択根拠・有意水準・サンプルサイズの決定方法を記述する

### Results
- `02_evidence.md` の証拠を論理的な順序で配置する（主張の流れに沿う）
- 結果の記述と解釈を混在させない（解釈は Discussion へ）
- 図表の参照順に沿って記述する
- 数値は平均 ± SD / SEM を明示し、n 数を必ず記載する

### Figure Legends

各図表の凡例を作成する:
- 図の内容が本文を参照しなくても理解できるよう自己完結させる
- `n =`（サンプル数）・エラーバーの定義（SD / SEM / 95% CI）・統計有意水準（* p < 0.05 等）を明示する
- `results/` のファイルと `02_evidence.md` の記述を照合して作成する

### Discussion
1. 主要な主張を証拠の強度とともに振り返る
2. 先行研究との比較（`Literature/` から）
3. 本研究の意義
4. Limitations（`03_gaps.md` の未解決事項を使う）
5. 今後の展望（`#open-question` から）

## 報告ガイドライン

研究デザインに応じて参照する:

| デザイン | ガイドライン |
|---|---|
| 動物実験 | ARRIVE 2.0 |
| 観察研究 | STROBE |
| 系統的レビュー / メタ解析 | PRISMA |
| 臨床試験 | CONSORT |
| 一般的な実験論文 | IMRAD |

---

### Stage 4 — Polishing（全モード共通）

Stage 2 または Stage 3 の完成ドラフトを全体的に磨く。内容の変更は行わず、**読みやすさと表現の質**を高める:

- **文章の流れ**: 段落間のつながりを確認し、唐突な展開を修正する
- **時制・態の一貫性**: 時制（過去形/現在形）と能動態・受動態の使い分けを統一する
- **冗長表現の削除**: "It is important to note that..." / "As mentioned above..." など、削除しても意味が変わらない表現を除去する
- **近接する繰り返し**: 同じ単語が近くに現れる箇所を言い換える
- **証拠の強度と表現の一致**: 断定が強すぎる箇所を証拠に見合った強度に調整する（"demonstrate" ↔ "suggest"）
- **`research-voice.md` の禁止表現を最終確認する**

Polishing 後は `drafts/v[n]-polished.md` として保存する。

## Vault への還元

- 執筆中に生まれた新しい洞察 → `Permanent/` への還元を提案する
- 執筆により更新が必要になった主張 → `01_claims.md` の修正を提案する
- 執筆後は `drafts/v[n].md` として保存し、`00_overview.md` のフェーズを更新する
