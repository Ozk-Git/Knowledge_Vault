# Knowledge Vault — 研究者のための AI 連携知識醸成システム

このリポジトリは、AI エージェントを「共同研究者」として迎え入れ、あなたの思考を構造化するための知識管理システムです。

以下の 3 つの強力な設計思想を融合させ、**「断片的なメモ」を「一本の論理的な論文」へと育てる**プロセスを、AI が伴走しながらサポートします。

1.  **Zettelkasten（ツェッテルカステン）**: 知識を連結し、複利的に成長させる手法。
2.  **LLM-Wiki (Andrej Karpathy)**: AI が「庭師」として知識ベースを動的に整理する概念。
3.  **obsidian-mind (breferrari)**: AI との対話を通じて思考を構造化するフレームワーク。

---

## 🌟 初めての方へ：このシステムは「メモアプリ」ではありません

通常のメモアプリ（Obsidian や Notion）と違うのは、**「あなたの意図を理解し、実際にファイルを整理してくれる AI 助手」が背後にいる**という点です。

-   **あなたは**: 自由にメモを書き、AI に「これを整理して」「この主張の証拠を探して」と指示を出します。
-   **AI は**: 指示に応えるだけでなく、セッション開始時に既存ノートの矛盾や弱い主張を能動的に指摘し、対話の中で「次の問い」を投げかけます。
-   **役割分担**: **「最終判断と創造的な思考」は人間が、「整理・検索・問いかけ」は AI が担当します。**

## 🚀 クイックスタート

### 1. 準備
ターミナルでリポジトリをクローンし、初期設定を行います。
＊事前にGitをインストールしてある必要があります。

```bash
git clone https://github.com/Ozk-Git/Knowledge_Vault.git
cd Knowledge_Vault
```

### 2. AI エージェントの起動
お好みの AI エージェント（Claude Code, Gemini CLI, Codex, または VS Code + Gemini Code Assist）をこのディレクトリ（Knowledge_Vault）で起動してください。

> **作者の環境について**: このシステムは **Obsidian + ACP プラグイン** をビューア・エディタとして使うことを前提に設計・運用しています。ただし、Markdown ファイルの読み書きさえできれば動作するため、AI エージェント CLI 単体でも、VS Code / Antigravity でも同様に利用できます。データ解析 → 論文執筆の流れでは、VS Code / Antigravity が便利だと思う人が多いかも。

**選択肢：**

- **ターミナル（推奨）**: Claude Code, Gemini CLI, Codex などの AI エージェント CLI を直接起動する方法です。システムの目的に最も沿った結果が得られます。
- **VS Code + AI 拡張**: Gemini Code Assist（Agent モード）や拡張機能の Claude Code や Codex を利用する方法です。ターミナル CLI に近い体験が手軽に得られます。VS Code / Antigravity もビューアとして活用できます。
- **Obsidian + ACP プラグイン**: Obsidian 上から AI エージェントを呼び出す方法です。ノートのビジュアル編集と AI 操作を一画面で行えます。
  - ACP プラグイン: https://github.com/RAIT-09/obsidian-agent-client

### 3. オプション設定（Zotero 連携）

Zotero を使っている場合、AI がライブラリを直接検索して PDF を読むことができます。

**設定手順（1回だけ）**

1. Zotero を開く
2. **環境設定 → 詳細 → ローカル API を有効にする** をオンにする

これだけで完了です。以降はセッション中に「Zotero で〇〇を検索して」と指示するだけで動作します。Zotero が起動していればMCPのインストールなしに利用できます。

> より高度な連携（ライブラリ管理・引用キー自動取得）が必要な場合は、`templates/paperdesk.md` の「推奨 MCP」セクションを参照してください。

### 4. セッション開始・終了（重要）
チャットを開始したら、まずエージェントにこう伝えてください：
> **「セッションを開始してください」**

**何が起きるか**: AI が `AGENTS.md` の規約を読み込み、Vault の統計・継続タスクを報告します。続けて **Probe**（既存ノートの矛盾・弱い主張・接続候補の能動的な問いかけ）を自動実行します。最初のメッセージからすぐに思考が深まります。

作業が終わったら：
> **「セッションを終了してください」**

**何が起きるか**: `index.md` と `log.md` を更新し、新しい問いを `Inbox/` に追加することを提案します。今セッションの作業要点を3行でまとめて報告します。

## 📖 AI との共同ワークフロー

AI への指示は、普段の言葉で OK です。AI が `AGENTS.md` の規約に従って動きます。
ただし、既存ファイルの上書き・移動・削除を行う前には必ず確認が入ります（**提案 → 確認 → 実行** の順）。

### Step 1: 情報の投入 (Ingest)
情報の種類に合わせて、以下の場所にファイルを放り込みます。
- **`Inbox/`**: ふと思いついたこと、走り書きのメモ。
- **`Clippings/`**: Web 記事や SNS で見つけた、後で読みたい外部情報。
- **`Daily/`**: 日々の実験ノート、会議記録、一日の振り返り。
- **`References/`**: 論文の PDF や書籍のデータ（永続保管用）。

`References/` の内部は自由です。年別・プロジェクト別など、必要に応じてサブディレクトリを切って構いません。

論文プロジェクトを進めている場合は、`Papers/[slug]/` 内にも実験・解析の記録を置けます。
- **`Papers/[slug]/experiments/`**: 実験ごとの記録（使用プロトコル・逸脱事項・結果サマリー）。`templates/pre-experiment.md` / `post-experiment.md` をひな形として使います。
- **`Papers/[slug]/results/`**: 図・データファイルと Figure legend。
- **`Papers/[slug]/protocols/`**: 実験プロトコルの詳細版。
- **`Papers/[slug]/scripts/`**: 解析コード。

これらは `Papers/[slug]/02_evidence.md` から相対パスでリンクされ、主張と実験記録が一本の線で繋がります。

投入後、AI に **「未処理のファイルを整理して」** と指示すると、AI が内容を要約し、`Literature/`（文献ノート）への保存案と、既存知識との関連を提案します。確認後に実行されます。

### Step 2: 知識への昇華 (Promote)
要約された内容を、一生モノの「自分の知識」に変えます。
- **指示例**: 「この文献ノートを永久ノートにして」「関連するノートを繋げて」
- **AI が行うこと**: 最小単位のノート（永久ノート）の作成案を提示。**既存ノートへのリンクを理由付きで提案**し、確認後に元ファイルを移動します。

### Step 3: 知識の体系化 (Wiki-Update)
バラバラな知識が増えてきたら、AI に全体像を描かせます。
- **指示例**: 「最近のノートを Wiki ページにまとめて」「[概念名] について知識を統合して」
- **AI が行うこと**: 複数のノートを横断検索。**`Permanent/` 内に**体系的な「Wiki ページ（`#wiki` タグ付き）」を作成し、知識の地図を更新します。

### Step 4: アウトプット (Paper-Work)
溜まった知識を、論文やプロジェクトの成果に繋げます。
- **指示例**: 「新しい論文プロジェクト [slug] を開始して」「この主張を支える証拠を Vault から探して」
- **AI が行うこと**: **`00_`〜`03_` の番号付き管理ファイルの作成を提案**。あなたの主張と、それを支える証拠（ノート、コード、データ）を一本の線で繋ぎ、論理の矛盾を指摘します。`templates/pre-experiment.md` / `post-experiment.md` を使った実験サイクル（計画 → 実施 → 解釈 → Permanent 還元）もサポートします。

## 🛠 論文専用モード：PaperDesk

論文を扱う際は、専用コマンド **`@paperdesk`** を使うか、**自然な言葉で指示を出すだけ**で、AI が「世界最高峰の専門査読者」の人格で対応します。

- **読解モード (Mode A)**: 他者の論文1本を深く理解し、Vault に統合します。図・データの批判的検討、主張と証拠のギャップ指摘、再現性評価を含みます。
  - **指示例**: PDF を指定して「この論文について解説して」「読解モードで要約して」
- **査読モード (Mode B)**: 投稿前の自分の論文を、実際の査読者の視点で冷徹に評価します。
  - **指示例**: 「この原稿について査読して」「査読モードでチェックして」
- **文献サーベイモード (Mode C)**: テーマを指定して複数論文を横断的に読み、フィールドの合意・矛盾・空白を整理します。Zotero・PubMed・Consensus・Scholar Gateway と連携して文献候補を収集します。
  - **指示例**: 「〇〇というテーマで文献サーベイして」「関連論文をまとめて整理して」

### その他の論文執筆エージェント

PaperDesk と並行して使える専用エージェントです。

- **`@drafting`**: 本文執筆支援。`01_claims.md` の主張と `02_evidence.md` の証拠を統合し、IMRAD構造に沿った英語原稿を作成します。**日本語で内容を整理してから学術英語に変換するモード**と**英語で直接書くモード**を選択できます。
  - **指示例**: 「Introduction を書いて」「Methods セクションのアウトラインを作って」
- **`@revision`**: 査読対応支援。受け取った査読コメントを分類し、Response letter を作成します。対応後に `03_gaps.md` と `01_claims.md` を自動更新します。
  - **指示例**: 「この査読コメントに返答して」「Reviewer 2 の Major Concern に対応して」
- **`@submission`**: 投稿前の最終準備を一括支援します。投稿規定の確認・原稿整形・補足資料作成・Figure legends・カバーレター作成・提出前チェックリストを順番に実行します。
  - **指示例**: 「投稿準備をして」「Nature Communications 向けに整形して」

### 執筆スタイルのカスタマイズ（research-voice.md）

`@drafting` は Vault ルートの `research-voice.md` を読み込み、あなたの文体・用語・禁止表現を論文執筆に反映します。

**作成手順（1回だけ）**

1. `templates/research-voice.md` を Vault ルートにコピーする
2. 自分の研究に合わせて編集する（推奨文型・統一用語・避けるべき表現など）

```bash
cp templates/research-voice.md research-voice.md
```

このファイルがない場合は汎用的な学術英語スタイルで執筆します。作成しておくと、論文ごとに用語やスタイルを指示し直す手間がなくなります。

### Zotero 連携

Zotero を使っている場合、3つのモードすべてで連携できます（クイックスタート「3. オプション設定」参照）。

- **「Zotero で〇〇を検索して」** と指示するだけで、ライブラリを検索して PDF を直接読み込みます
- PDF は Zotero ストレージから直接読むため、`References/` へのコピーは不要です（キー文献として確定した時点でコピーを提案します）
- 読み込んだ論文は自動的に Mode A で解析され、`Literature/` にノートが作成されます
- ZotMoov などのリンクファイル管理ツールを使っていても問題ありません

## 💡 蓄積した知識の活用例

-   **実験ノートを論文の証拠にする**: `Daily/` の実験結果を AI が `Permanent/`（証拠）へ昇華させ、`02_evidence.md` にリンクします。
-   **解析コードと主張を直結させる**: どの図表（results）がどのコード（scripts）で生成されたかを AI が把握し、論文の信頼性を担保します。
-   **AI が「論理の番人」になる**: 執筆中、AI に「主張と証拠に矛盾がないかチェックして」と頼み、質の高い構成を維持します。
-   **Connect でセレンディピティを引き出す**: AI が Lint と並行して「離れたノート間の予期しない接続」を自動提案します。バラバラに見えた知識が、ある日突然一本の仮説に繋がります。

## 📂 ディレクトリの役割（人間と AI の共有地）

| ディレクトリ | 役割 | 入れるもの |
|---|---|---|
| `Inbox/` | **思いつきの入り口** | メモ、走り書き、アイデア |
| `Clippings/` | **外部情報の入り口** | Web 記事、SNS 魚拓、ニュース |
| `Daily/` | **活動の記録** | 実験ノート、日報、会議メモ |
| `Literature/` | AI が作った要約 | AI が生成した文献ノート（叩き台） |
| `Permanent/` | **思考の中核** | 永久ノート、Wiki ページ（知識の網） |
| `References/` | **永続保管庫** | 論文 PDF、書籍ファイル（移動・削除厳禁） |
| `Papers/` | 論文ワークスペース | 論文プロジェクトごとの設計図と執筆原稿 |

## 🏷 タグ体系

AI と人間がノートの状態を共有するために、以下のタグを使用します。

| タグ | 意味 | 運用 |
|---|---|---|
| `#llm-draft` | **AI 生成ドラフト** | 内容を確認し、自分の言葉に修正したら外してください。 |
| `#wiki` | **知識統合ページ** | 複数のノートを AI が横断的にまとめたノートに付きます。 |
| `#paper-relevant` | **論文関連** | 執筆中の論文に直接関連する知見に付きます。 |
| `#open-question` | **未解決の問い** | 追加の実験や調査が必要な事項に付きます。 |
| `#claim` | **論文の主張** | 論文のコアとなる主張（またはその候補）に付きます。 |
| `#established` | **確立した知識** | 文献・実験で十分に裏付けられた知識に付きます。 |
| `#hypothesis` | **仮説** | 自分が立てた未検証の仮説に付きます。 |
| `#my-interpretation` | **独自解釈** | データや文献への独自の解釈に付きます。 |

## ⚠️ 注意事項

-   **動作仕様の正本**: このドキュメントは概要説明です。AI の具体的な動作ルールは **`AGENTS.md`（および `Papers/AGENTS.md`）が正本**です。内容が矛盾する場合は `AGENTS.md` を優先してください。
-   **手動編集の制限**: `index.md` や `log.md` は AI が自動管理します。手動で書き換えると AI が混乱するため、AI に更新を任せててください。
-   **タグの活用**: AI が生成したノートには `#llm-draft` が付きます。内容を確認したら、このタグを外してください。それが「人間の承認」の印になります。
-   **MCP (外部連携)**: Zotero や PubMed と連携設定を行うことで、AI が直接文献を検索したり、引用キーを取得したりできるようになります。

## 🚀 さらに使い倒すためのヒント

### 1. セッション開始時の Probe を活用する
「セッションを開始してください」と伝えると、AI が **Probe**（能動的問いかけ）を自動実行します。
- 最近 Ingest されたノートと既存 Permanent ノートの矛盾・補完関係を報告
- 証拠が薄い `状態: 確定` の Claim を指摘
- 既存知識で答えられそうな `#open-question` を提案
- 長期放置のノートと最近の知識の接続を問いかけ

最初のメッセージから思考が深まるよう設計されています。

### 2. AI との議論を Vault に記憶させる (Remember)
研究の方針を決めた議論、実験デザインの選択理由、解釈の変遷——こうした「判断の背景」は、ノートには残りにくいものです。
AI に **「議論を記憶してください」** と伝えると、現セッションの決定事項・背景・今後の方針を Vault 内に保存します。

- 端末や AI エージェントが変わっても、判断の文脈を引き継げます
- 保存先は内容に応じて自動判断されます（論文プロジェクト固有なら `Papers/slug/context/`、Vault 全体に関わるなら `rules/session-memory.md`）

### 3. Vault の「健康診断」を依頼する (Lint + Connect)
ノートが増えてきたら、AI に **「Vault の健全性チェック（Lint）をして」** と頼んでください。
- 誰からもリンクされていない「孤立ノート」の発見
- 複数のノート間に潜む「論理的な矛盾」の指摘
- 放置された `#llm-draft`（未承認ノート）のリストアップ

Lint と同時に **Connect**（セレンディピティ探索）も実行されます。2週間以上前のノートと最近のノートの「予期しない接続」を AI が提案します。

### 4. エージェントの「得意分野」を使い分ける
- **Claude Code**: 高い論理的推論が得意。論文の「執筆」や「複雑なロジックの整理」に最適です。
- **Gemini CLI / Gemini Code Assist**: 圧倒的なコンテキスト（記憶容量）が武器。大量の PDF の一括処理や、Vault 全体を俯瞰した検索に強みを発揮します。
- **Codex**: 汎用的な操作やスクリプト実行など、日常的なメンテナンスに。

### 5. 「#llm-draft」タグを外すことの意味
AI が生成したノートには必ず `#llm-draft` タグが付きます。
このタグを外すことは、単なる作業ではなく、**「私がこの知識を承認した」という責任ある宣言**です。AI の生成物をそのままにせず、自分の言葉で微調整してタグを外す。この「ひと手間」が、あなたの Vault を「単なる AI の出力先」から「あなたの真の知性」へと変えます。

### 6. このシステム自体を AI と一緒に育てる
機能の追加や改善のアイデアが浮かんだら、作者の対応を待つ必要はありません。`AGENTS.md` や `rules/` のファイルはただのテキストです。AI エージェントに「こういう操作を追加したい」「この手順を変えたい」と相談しながら、自分の研究スタイルに合わせて改造してください。このシステム自体も、まさにそうやって作られました。

### 5. 複数端末で Git 同期する場合の注意点（上級者向け）
この Vault は Git で同期できますが、`index.md` と `log.md` は AI が自動更新する共有状態ファイルなので、複数端末で並行して使うと競合しやすくなります。
個人利用であれば通常は問題ありませんが、複数端末で編集する場合は、AIエージェント起動前に pull し、競合時は `log.md` を append-only の履歴として保ちながら手動で整合を取ってください。
どの Git 運用（merge / rebase など）を採るかは利用者の判断に委ねられます。
