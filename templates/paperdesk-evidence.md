# PaperDesk — 科学的根拠チェック（モード D）

生物学・医学・情報学・物理学などの科学的主張について、
既存研究の支持状況を素早く確認する。

**用途**: ユーザーが「科学的根拠はあるか」「この主張は論文で支持されるか」
「記事や原稿に入れてよい表現か」を確認したいときに使う。

Mode D は Literature ノート作成や Ingest を自動実行しない。
必要な場合のみ、最後にノート化・Ingest を提案する。

---

## 共通原則

- **正確性の追求**: ハルシネーションを極限まで排除する
- **不可知の明示**: 論文に記載がないことは「記載なし」と明示し、推測で補わない
- **根拠の強さを分ける**: 観察研究、介入研究、RCT、メタ解析、ガイドラインを区別する
- **断定の抑制**: 医療・健康・投資など高リスク領域では、実践推奨を断定しない
- **出力言語**: 思考プロセスは英語、ユーザーへの出力はすべて日本語

---

## Step 0 — 主張の分解

ユーザーの問いを、検証可能な主張に分解する。

必要に応じて、対象者、介入・曝露、比較対象、アウトカム、時間軸を明示する。

---

## Step 1 — Consensus による一次確認

**Consensus MCP を主入口として使用する。**

検索時は、主張を英語の短いリサーチクエスチョンに変換する。
結果を読むときは、以下を確認する:

- 支持する論文が多いか
- 反対・矛盾する論文があるか
- 研究の種類（RCT、メタ解析、観察研究、レビューなど）
- 対象者・条件がユーザーの文脈に合っているか
- 効果量やアウトカムが実用上意味のあるものか

Consensus の結果をそのまま結論にせず、必要に応じて Step 2 で一次文献を確認する。

---

## Step 2 — 補助検索と一次文献確認

必要に応じて以下を使う:

| 情報源 | 用途 |
|---|---|
| PubMed | 医学・生命科学の一次文献、レビュー、ガイドライン確認 |
| Semantic Scholar | 分野横断の関連論文・被引用関係確認 |
| Zotero | 既にVault利用者が保存している論文の確認 |
| OpenAlex | OA文献やメタデータの補完 |

優先順位:

1. システマティックレビュー / メタ解析
2. ガイドライン / 専門学会声明
3. RCT / 介入研究
4. 前向きコホート
5. 横断研究・症例報告
6. 動物実験・in vitro・メカニズム仮説

---

## Step 3 — 支持状況の分類

結論は以下のいずれかに分類する:

| 分類 | 意味 |
|---|---|
| 支持される | 複数の質の高い研究が一貫して支持する |
| 限定的に支持 | 一定の根拠はあるが、対象者・条件・効果量に制限がある |
| 矛盾あり | 支持・不支持の研究が混在し、条件差や手法差の整理が必要 |
| 根拠不足 | 直接検証した研究が乏しい、または質が低い |
| 根拠なしに近い | 主要な研究で支持されず、主張が過大である可能性が高い |

---

## Step 4 — 出力形式

```md
## 結論

分類: 支持される / 限定的に支持 / 矛盾あり / 根拠不足 / 根拠なしに近い

1〜3文で結論を書く。

## 根拠

- 代表的な研究・レビュー・ガイドラインを、研究タイプと対象者つきで整理する
- Consensus を使った場合は、検索結果から見える全体傾向を要約する
- 必要に応じて PubMed / Semantic Scholar / Zotero で確認した一次文献を併記する

## 注意点

- 対象者の違い
- 効果量の大きさ
- 研究デザイン上の限界
- 実践・記事化するときに避けるべき言い切り

## 使える表現

記事や原稿に使う場合、科学的に安全な表現を提案する。
```

---

## Step 5 — Vault への接続提案

以下の条件を満たす場合のみ、追加作業を提案する:

- 今後も参照する科学的根拠である
- 記事や Papers/ の主張を支える根拠になる
- 複数論文を読解して Literature 化する価値がある

提案例:

- `Literature/` に根拠ノートを作成する
- `Papers/[slug]/02_evidence.md` に追加する
- Mode C / survey に切り替えて、関連論文を横断サーベイする
